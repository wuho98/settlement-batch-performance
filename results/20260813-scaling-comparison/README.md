# 100k · 500k · 1m scaling comparison

## 최종 집계 입력

| 데이터 | 실행 ID | 상태 |
| ---: | --- | --- |
| 100,000 | `20260813-100k-baseline-02` | 최종 집계 사용 |
| 500,000 | `20260813-500k-baseline-01` | 최종 집계 사용 |
| 1,000,000 | `20260813-1m-baseline-02` | 최종 집계 사용 |
| 1,000,000 | `20260813-1m-baseline-01` | 시계 이상치 원본 보존, 최종 집계 제외 |

## 평균 Step 실행 시간

| 데이터 | JpaPaging | Zero Offset | Zero/Paging | Paging 10만 대비 | Zero 10만 대비 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 100,000 | 1,432.997ms | 865.282ms | 60.4% | 1.00배 | 1.00배 |
| 500,000 | 18,522.257ms | 4,199.500ms | 22.7% | 12.93배 | 4.85배 |
| 1,000,000 | 125,905.933ms | 9,139.061ms | 7.3% | 87.86배 | 10.56배 |

데이터가 10배일 때 Paging 평균은 87.86배, Zero Offset 평균은 10.56배로 증가했다. 이번 환경에서는 데이터가 커질수록 Paging의 증가 폭이 더 컸다.

## 집계 방법

- `phase=MEASURED`인 Reader별 3개 `stepDurationNanos`를 ms로 변환
- 평균은 3개 값의 산술평균, 중앙값은 정렬한 가운데 값
- Zero/Paging은 같은 데이터 규모의 두 평균 비율
- 증가 배율은 각 Reader의 10만 건 평균을 기준으로 계산
- 페이지 구간 평균은 측정 3회 × 해당 구간 10개 page의 평균
- 데이터를 반환하지 않는 마지막 빈 page는 페이지 추세에서만 제외

## 정합성 및 이상치

최종 집계에 사용한 24회 Job은 모두 데이터셋 크기와 read/write 건수가 일치했고 skip·rollback은 0이었다. 첫 100만 건 실행의 시계 이상치는 통합 결과표의 `Anomalies` 시트와 해당 실행의 `NOTES.md`에 보존했다.

`benchmark-comparison.xlsx`에는 최종 요약, 증가 추세 차트, 페이지 구간 추세, 24회 개별 실행값, 측정 페이지 원본, 이상치, 환경을 수식 기반으로 정리했다.
